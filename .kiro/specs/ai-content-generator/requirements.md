# Requirements Document

## Introduction

The AI Content Generator is a feature for LateWiz that enables users to automatically generate, curate, and schedule social media content using free AI services. The system leverages Groq's free LLM API (Llama 3.3 70B) for text generation, Pixabay's free API for royalty-free stock images, and Pollinations.ai's free URL-based service for AI-generated images. All external API calls are made server-side through Next.js API routes to keep API keys secure. The feature integrates directly into LateWiz's existing compose and scheduling pipeline, with users maintaining full control through a review-and-edit step before any AI-generated post is published or scheduled.

## Glossary

- **AI_Settings_Store**: A Zustand store that persists brand configuration, generation preferences, auto-schedule configuration, and generation history to localStorage
- **Server_API_Route**: A Next.js App Router API route handler that proxies external API calls server-side
- **Content_Generation_Route**: The `/api/ai/generate-content` server route that calls the Groq API to generate social media content variants
- **Image_Search_Route**: The `/api/ai/search-images` server route that queries the Pixabay API for royalty-free stock images
- **AI_Image_Route**: The `/api/ai/generate-image` server route that generates images via Pollinations.ai and re-uploads them to Zernio storage
- **Trending_Topics_Route**: The `/api/ai/trending-topics` server route that queries the Groq API for trending content topics
- **Auto_Schedule_Route**: The `/api/ai/auto-schedule` server route that generates a batch of draft posts across a schedule
- **AI_Hooks**: TanStack Query mutation hooks that wrap server API route calls for client-side use
- **AI_Generator_Page**: The main UI page providing a multi-step workflow for AI content generation
- **Review_Queue**: A UI panel where users review, edit, approve, or discard AI-generated draft posts
- **BrandProfile**: A data model storing brand name, description, tone, voice, target audience, industry, hashtags, do/don't lists, and default CTA
- **GenerationPrefs**: A data model storing default model, temperature, max tokens, number of variants, and inclusion toggles for hashtags, emoji, and CTA
- **AutoScheduleConfig**: A data model storing auto-schedule frequency, posts per week, posting times, content themes, and date range
- **ContentVariant**: A data model representing one generated content option with content, hashtags, image suggestion, CTA, character count, platform validity, and warnings
- **GeneratedPostDraft**: A data model representing a draft AI-generated post with content, media, platforms, status, and brand snapshot
- **DraftScheduledPost**: A data model representing a post generated by auto-scheduling, always with status "draft"
- **ContentTheme**: A data model representing a content category with name, description, and weight for weighted distribution
- **TrendingTopic**: A data model representing a trending topic with topic, angle, whyItTrends, and contentIdeas
- **StockImage**: A data model representing a Pixabay image result with url, previewUrl, tags, dimensions, and source
- **PlatformConstraints**: Platform-specific limits for character count, hashtag count, and content formatting
- **Rate_Limiter**: A server-side in-memory rate limiting mechanism using a Map with TTL
- **Groq_API**: The external Groq LLM API service used for text generation and trending topics
- **Pixabay_API**: The external Pixabay API service used for royalty-free image search
- **Pollinations_API**: The external Pollinations.ai URL-based service used for AI image generation
- **Zernio_Storage**: The existing LateWiz media storage system accessed via presigned URLs
- **createPost**: The existing LateWiz mutation for creating and scheduling posts
- **MediaItem**: The existing LateWiz data type representing media attached to a post
- **PlatformPost**: The existing LateWiz data type representing a platform and account pairing for a post

## Requirements

### Requirement 1: AI Text Generation

**User Story:** As a content creator, I want to generate social media post content using AI, so that I can quickly produce multiple content variants tailored to my brand and platform.

#### Acceptance Criteria

1. WHEN a valid content generation request with a non-empty topic, valid platform, and BrandProfile is received, THE Content_Generation_Route SHALL call the Groq_API with a system prompt and user prompt to generate content variants
2. THE Content_Generation_Route SHALL return at least one ContentVariant in the response
3. THE Content_Generation_Route SHALL populate each ContentVariant with a unique id, content, hashtags, imageSuggestion, callToAction, characterCount, platformValid, and warnings
4. WHEN the Groq_API response contains valid JSON, THE Content_Generation_Route SHALL parse the JSON and build variants from the parsed content
5. WHEN the Groq_API response cannot be parsed as JSON, THE Content_Generation_Route SHALL invoke extractContentFallback to extract at least one variant from raw text
6. THE Content_Generation_Route SHALL set characterCount equal to the length of content for each variant
7. THE Content_Generation_Route SHALL set platformValid to true if and only if content length is within the platform-specific character limit
8. WHEN content exceeds the platform character limit, THE Content_Generation_Route SHALL populate warnings with a description of the violation
9. THE Content_Generation_Route SHALL NOT include any API keys in the response body or headers

### Requirement 2: Royalty-Free Image Sourcing

**User Story:** As a content creator, I want to search for royalty-free stock images, so that I can find relevant visuals for my posts without licensing concerns.

#### Acceptance Criteria

1. WHEN a valid search query (1-100 characters) and per-page count (1-200) are provided, THE Image_Search_Route SHALL query the Pixabay_API with safesearch enabled and horizontal orientation
2. THE Image_Search_Route SHALL return at most the requested number of StockImage objects in the response
3. THE Image_Search_Route SHALL populate each StockImage with id, url, previewUrl, tags, width, height, and source set to "pixabay"
4. WHEN the Pixabay_API returns a non-200 status or times out, THE Image_Search_Route SHALL return an HTTP 502 error response
5. THE Image_Search_Route SHALL NOT include the PIXABAY_API_KEY in any image object or response field
6. THE Image_Search_Route SHALL sanitize the search query by URL-encoding it and removing control characters before sending to Pixabay_API
7. IF an invalid search query (empty or exceeding 100 characters) or invalid per-page count (outside 1-200) is provided, THE Image_Search_Route SHALL return an HTTP 400 validation error
8. IF the PIXABAY_API_KEY environment variable is not set, THE Image_Search_Route SHALL return an HTTP 500 server error indicating the API key is missing

### Requirement 3: AI Image Generation

**User Story:** As a content creator, I want to generate custom AI images from text prompts, so that I can create unique visuals that match my content.

#### Acceptance Criteria

1. WHEN a valid image generation request with a non-empty prompt (1-500 characters), width (256-2048), height (256-2048), and model ("flux" or "turbo") is received, THE AI_Image_Route SHALL fetch an image from Pollinations_API using the URL-encoded prompt, width, height, model, and nologo parameters
2. IF the Pollinations_API returns a non-200 status or times out after 60 seconds, THE AI_Image_Route SHALL return an HTTP 502 error response
3. WHEN the image is successfully fetched from Pollinations_API, THE AI_Image_Route SHALL upload the image binary to Zernio_Storage via a presigned URL obtained from getMediaPresignedUrl
4. IF the presigned URL upload returns a non-200 status, THE AI_Image_Route SHALL return an HTTP 500 error response and SHALL NOT expose the Pollinations_API URL to the client
5. WHEN the upload succeeds, THE AI_Image_Route SHALL return a response with the Zernio-hosted public URL, type set to "image", and the requested width and height
6. THE AI_Image_Route SHALL NOT include the Pollinations_API URL or any API keys in the response
7. WHERE the model parameter is omitted, THE AI_Image_Route SHALL default to "flux"
8. WHERE the width or height parameter is omitted, THE AI_Image_Route SHALL default to 1024 for each
9. IF an invalid image generation request with an empty prompt, out-of-range dimensions, or unsupported model is received, THE AI_Image_Route SHALL return an HTTP 400 validation error

### Requirement 4: Branding Context Management

**User Story:** As a brand manager, I want to configure and persist my brand guidelines, so that AI-generated content consistently reflects my brand voice and tone.

#### Acceptance Criteria

1. THE AI_Settings_Store SHALL persist the BrandProfile, GenerationPrefs, AutoScheduleConfig, and generationHistory to localStorage under the key "latewiz-ai-settings"
2. WHEN a user updates the BrandProfile, THE AI_Settings_Store SHALL merge the partial update with the existing profile, or if no existing profile exists, SHALL use the partial update as the initial profile
3. WHEN a user updates the GenerationPrefs, THE AI_Settings_Store SHALL merge the partial update with the existing preferences, or if no existing preferences exist, SHALL use the partial update as the initial preferences
4. WHEN a user updates the AutoScheduleConfig, THE AI_Settings_Store SHALL merge the partial update with the existing configuration, or if no existing configuration exists, SHALL use the partial update as the initial configuration
5. WHEN a draft is added to generationHistory, THE AI_Settings_Store SHALL prepend it to the history array and truncate the array to a maximum of 50 entries
6. THE AI_Settings_Store SHALL provide a clearGenerationHistory action that empties the generationHistory array
7. WHERE the brandName field is provided, THE AI_Settings_Store SHALL validate it as non-empty with a maximum of 100 characters
8. WHERE the tone field is provided, THE AI_Settings_Store SHALL validate it as non-empty with a maximum of 50 characters
9. WHERE hashtags are provided, THE AI_Settings_Store SHALL validate that each tag starts with "#" and the array contains a maximum of 30 tags
10. WHERE doList or dontList items are provided, THE AI_Settings_Store SHALL validate a maximum of 10 items per list with a maximum of 200 characters per item
11. IF any BrandProfile field validation fails, THE AI_Settings_Store SHALL reject the BrandProfile update, retain the existing valid data unchanged, and return a validation error indicating the specific field that failed validation
12. WHERE the description, voice, targetAudience, industry, or defaultCTA field is provided, THE AI_Settings_Store SHALL validate each as non-empty with a maximum of 500 characters for description, 200 characters for voice, 200 characters for targetAudience, 100 characters for industry, and 200 characters for defaultCTA

### Requirement 5: Trending Topics Discovery

**User Story:** As a content creator, I want to discover trending topics in my niche, so that I can generate timely and relevant content.

#### Acceptance Criteria

1. WHEN a valid trending topics request with a non-empty niche (1-200 characters) is received, THE Trending_Topics_Route SHALL call the Groq_API with a prompt requesting trending topics for the given niche
2. THE Trending_Topics_Route SHALL return a non-empty array of TrendingTopic objects (maximum 10), each with a unique id, topic, angle, whyItTrends, and contentIdeas (string array, maximum 5 items)
3. WHEN the brandContext is provided in the request, THE Trending_Topics_Route SHALL include the brand name, target audience, and industry in the Groq_API prompt
4. IF the Groq_API response cannot be parsed as JSON, THE Trending_Topics_Route SHALL invoke a fallback extraction to produce at least one topic with topic, angle, whyItTrends, and contentIdeas fields
5. THE Trending_Topics_Route SHALL NOT include any API keys in the response
6. THE AI_Hooks SHALL cache trending topics results for 1 hour using a cache key derived from the niche and brandContext to avoid unnecessary API calls
7. IF an invalid trending topics request with an empty niche or a niche exceeding 200 characters is received, THE Trending_Topics_Route SHALL return an HTTP 400 validation error
8. WHEN the Groq_API returns a non-200 status or times out, THE Trending_Topics_Route SHALL return an HTTP 502 error response

### Requirement 6: Auto-Scheduling with User Approval

**User Story:** As a content manager, I want to automatically generate and schedule a batch of posts, so that I can maintain a consistent posting cadence without manual effort for each post.

#### Acceptance Criteria

1. WHEN a valid auto-schedule request with an enabled config, non-empty contentThemes, non-empty platforms, and valid timezone is received, THE Auto_Schedule_Route SHALL calculate schedule slots based on postsPerWeek, frequency, and postingTimes
2. THE Auto_Schedule_Route SHALL select a theme for each slot using weighted distribution across contentThemes
3. THE Auto_Schedule_Route SHALL generate content for each slot by calling the Content_Generation_Route with the slot's theme as the topic
4. THE Auto_Schedule_Route SHALL search for images for each slot based on the generated variant's imageSuggestion
5. THE Auto_Schedule_Route SHALL return DraftScheduledPost objects, each with content, hashtags, mediaUrls, platforms, scheduledFor, topic, and status
6. THE Auto_Schedule_Route SHALL set the status of every DraftScheduledPost to "draft"
7. THE Auto_Schedule_Route SHALL NOT publish any post automatically without user approval
8. WHEN a user approves a draft, THE Review_Queue SHALL submit the post via the existing createPost mutation
9. WHEN a user discards a draft, THE Review_Queue SHALL remove the draft from the queue without submitting it
10. THE Auto_Schedule_Route SHALL set scheduledFor to a valid ISO timestamp in the future for every draft
11. WHERE the contentThemes weights do not sum to 1.0, THE Auto_Schedule_Route SHALL reject the request with a validation error

### Requirement 7: Security and API Key Isolation

**User Story:** As a system administrator, I want all API keys to remain server-side, so that sensitive credentials are never exposed to the client.

#### Acceptance Criteria

1. THE Server_API_Route SHALL access all external API keys exclusively from server-side environment variables
2. THE Server_API_Route SHALL NOT include GROQ_API_KEY, PIXABAY_API_KEY, or any other API key value in any response body or header
3. THE Server_API_Route SHALL NOT echo API keys in error messages or logs
4. WHEN user-provided text is inserted into prompts, THE Content_Generation_Route SHALL sanitize the text to remove control characters, null bytes, and instruction override attempts
5. THE Server_API_Route SHALL validate all inputs server-side using Zod schemas with length limits and character restrictions
6. THE Server_API_Route SHALL always prepend the system prompt before user input to prevent instruction injection override
7. THE Content_Generation_Route SHALL use the dontList from BrandProfile to specify topics or words to avoid in generated content

### Requirement 8: Rate Limiting

**User Story:** As a system operator, I want rate limits enforced on external API calls, so that free-tier API quotas are not exhausted and the service remains available.

#### Acceptance Criteria

1. THE Rate_Limiter SHALL enforce per-provider, per-identifier limits: Groq at 30 requests per 60 seconds, Pixabay at 100 requests per 60 seconds, and Pollinations at 10 requests per 60 seconds
2. WHEN the request count for a provider and identifier exceeds the limit within the 60-second window, THE Rate_Limiter SHALL return false to reject the request
3. WHEN the rate limit is exceeded, THE Server_API_Route SHALL return an HTTP 429 response with a descriptive error message
4. WHEN the 60-second window expires, THE Rate_Limiter SHALL reset the request count for that provider and identifier
5. THE Rate_Limiter SHALL namespace cache keys by provider and identifier using the format "ratelimit:{provider}:{identifier}"
6. WHEN the request count is below the limit, THE Rate_Limiter SHALL increment the count and return true to allow the request

### Requirement 9: Error Handling and Fallback Resilience

**User Story:** As a user, I want the system to gracefully handle external API failures, so that I am not blocked when a free-tier service is temporarily unavailable.

#### Acceptance Criteria

1. WHEN the Groq_API returns a non-200 status or times out, THE Content_Generation_Route SHALL return an HTTP 502 error, and THE AI_Hooks SHALL retry up to 2 times with exponential backoff before falling back to Gemini API
2. WHEN both Groq_API and Gemini API fail, THE AI_Hooks SHALL display a user-friendly error message with a retry button
3. WHEN the Pixabay_API returns a non-200 status, THE Image_Search_Route SHALL return an HTTP 502 error, and THE AI_Hooks SHALL retry once before falling back to Unsplash API
4. WHEN both Pixabay_API and Unsplash API fail, THE AI_Hooks SHALL allow the user to manually upload images via the existing MediaUploader component
5. WHEN the Pollinations_API returns a non-200 status or times out, THE AI_Image_Route SHALL return an HTTP 502 error, and THE AI_Hooks SHALL retry once with the alternate model (flux to turbo)
6. WHEN the Pollinations_API retry also fails, THE AI_Hooks SHALL suggest using royalty-free image search as a fallback
7. WHEN the Zernio presigned URL operation fails during AI image upload, THE AI_Image_Route SHALL return an HTTP 500 error, and the user SHALL be able to retry image generation or use stock images
8. WHEN the Groq_API returns malformed JSON that cannot be parsed, THE Content_Generation_Route SHALL invoke extractContentFallback to attempt content extraction from raw text
9. WHEN extractContentFallback produces at least one variant, THE Content_Generation_Route SHALL return the extracted variants; WHEN extraction fails entirely, THE Content_Generation_Route SHALL return an HTTP 502 error
10. WHEN a user attempts to generate content without configuring a BrandProfile, THE AI_Generator_Page SHALL prompt the user to configure brand settings while allowing generation to proceed with default empty context
11. THE fallback provider response SHALL maintain the same interface contract as the primary provider response

### Requirement 10: Review and Approval Queue

**User Story:** As a content creator, I want to review and edit AI-generated drafts before publishing, so that I maintain full control over what gets posted.

#### Acceptance Criteria

1. THE AI_Generator_Page SHALL display generated ContentVariants for user selection and inline editing
2. WHEN a user selects a variant, THE AI_Generator_Page SHALL navigate to the existing Compose page with the variant content prefilled
3. THE Review_Queue SHALL display DraftScheduledPost objects with options to approve, edit, or discard each draft
4. THE GeneratedPostDraft status SHALL transition only through the sequence: draft to approved to scheduled, or draft to discarded
5. WHEN a user edits a draft, THE Review_Queue SHALL allow modification of content, hashtags, and media before approval
6. THE AI_Generator_Page SHALL display platform-specific previews using the existing PlatformPreviews component
7. THE AI_Generator_Page SHALL show real-time loading states during AI generation operations

### Requirement 11: Platform Constraint Enforcement

**User Story:** As a content creator, I want the system to enforce platform-specific content limits, so that my posts are valid for each platform before publishing.

#### Acceptance Criteria

1. THE Content_Generation_Route SHALL enforce character limits per platform: twitter at 280, instagram at 2200, linkedin at 3000, facebook at 63206, and others at 5000
2. THE Content_Generation_Route SHALL enforce hashtag count limits per platform: twitter at 2, instagram at 30, linkedin at 5, facebook at 10, and others at 10
3. WHEN hashtags are validated, THE Content_Generation_Route SHALL ensure each returned hashtag starts with "#"
4. WHEN hashtags are validated, THE Content_Generation_Route SHALL remove empty tags and truncate the array to the platform-specific maximum
5. THE Content_Generation_Route SHALL NOT mutate the input hashtag array during validation
6. WHEN content length exceeds the platform character limit, THE Content_Generation_Route SHALL set platformValid to false
7. WHEN content length is within the platform character limit, THE Content_Generation_Route SHALL set platformValid to true

### Requirement 12: Prompt Construction

**User Story:** As a developer, I want prompts to be constructed with brand context and platform constraints, so that AI-generated content is relevant and platform-appropriate.

#### Acceptance Criteria

1. WHEN a BrandProfile is provided, THE buildSystemPrompt function SHALL include the brand name, tone, voice, and target audience in the system prompt
2. THE buildSystemPrompt function SHALL include platform-specific constraints in the system prompt
3. THE buildSystemPrompt function SHALL NOT contain unsanitized user-provided content
4. THE buildSystemPrompt function SHALL return a string that does not exceed 4000 characters
5. THE buildUserPrompt function SHALL include the topic, optional tone override, platform constraints, variant count, and JSON output format instructions
6. THE buildUserPrompt function SHALL return a non-empty string that does not exceed 2000 characters
7. WHERE numVariants is omitted, THE buildUserPrompt function SHALL default to 3 variants

### Requirement 13: Auto-Schedule Configuration Validation

**User Story:** As a content manager, I want auto-schedule configuration to be validated before execution, so that invalid configurations are caught early.

#### Acceptance Criteria

1. WHERE postsPerWeek is provided, THE system SHALL validate it as an integer between 1 and 14
2. WHERE postingTimes are provided, THE system SHALL validate each entry as "HH:MM" format with a maximum of 7 entries
3. WHERE contentThemes are provided and auto-scheduling is enabled, THE system SHALL validate that at least 1 theme exists
4. WHERE contentTheme weights are provided, THE system SHALL validate that the sum of all weights equals 1.0
5. WHERE startDate is provided, THE system SHALL validate it as today or a future date
6. WHERE endDate is provided, THE system SHALL validate it as a date after startDate
7. WHEN the auto-schedule configuration is invalid, THE AI_Generator_Page SHALL prevent submission and display field-level error messages

### Requirement 14: Generation Preferences Validation

**User Story:** As a user, I want to configure AI generation preferences, so that content is generated according to my preferred settings.

#### Acceptance Criteria

1. WHERE temperature is provided, THE system SHALL validate it as a number between 0.0 and 1.0 inclusive
2. WHERE maxTokens is provided, THE system SHALL validate it as an integer between 256 and 4096
3. WHERE numVariants is provided, THE system SHALL validate it as an integer between 1 and 5
4. WHERE defaultModel is provided, THE system SHALL validate it as a valid Groq model identifier ("llama-3.3-70b" or "llama-3.1-8b")

### Requirement 15: Integration with Existing Compose Pipeline

**User Story:** As a developer, I want AI-generated content to flow through the existing compose pipeline, so that it benefits from the same scheduling and publishing infrastructure as manual posts.

#### Acceptance Criteria

1. WHEN an AI-generated post is approved, THE Review_Queue SHALL submit it via the existing createPost mutation
2. WHEN media is attached to an AI-generated post, THE system SHALL conform media items to the existing MediaItem type
3. WHEN platforms are specified for an AI-generated post, THE system SHALL conform platform entries to the existing PlatformPost type
4. THE AI_Generator_Page SHALL navigate to the existing Compose page with prefilled content when a variant is selected
5. THE Content_Generation_Route SHALL space auto-schedule content generation requests at least 2 seconds apart to respect rate limits
6. THE AI_Hooks SHALL cache Pixabay image search results with a 5-minute stale time to avoid redundant API calls
